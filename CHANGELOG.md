## [1.1.0] - 2026-08-22

Measured on Unilog's official 1,000-row dataset. Every figure below was
re-measured at the commit it is compared against rather than quoted from
notes.

### Accuracy

- **Auto-approval 20.0% → 64.8%** (200 → 648 of 1,000 rows) and **field verified rate 38.1% → 51.5%.** Two thirds of the gain was a defect rather than missing data: `match_brand()` searched only the brand index, which had been written for the valve vertical, so DEWALT, Leviton, 3M, Square D and Diablo scored 0.0 as brands while resolving cleanly against the manufacturer index one lookup over.
- **Distributor recognition.** `Part_Manuf` in the supplied feed frequently names a distributor rather than a manufacturer. Boise Cascade, Appliance Dealers Cooperative, Parksite, U S Lumber and others are now identified as distributors; the manufacturer stays unresolved and the evidence records `distributor_not_manufacturer`. This deliberately forgoes roughly seven points of headline accuracy on 288 rows.
- **Curated reference data** (`data/reference/`) covering the names this dataset actually contains. The 1,117 unresolved fields collapsed to 100 distinct strings, so the previously-stated need for a 27,000-row vocabulary was wrong.

### Added

- **JSON and XML catalogue ingestion**, and **TXT, DOCX and RTF document ingestion**, alongside the existing CSV/TSV/XLSX/PDF. Nine formats total, resolved by one module so the endpoint, the reader and the UI cannot drift apart.
- **Unsupported formats are refused with a reason and a remedy**, in the browser, before any bytes are sent. Images, audio, video, archives, executables and disk images are rejected; legacy `.xls` and `.doc` name their modern replacement.
- **Datasheet-to-row linking.** `GET /documents/for-part/{part_number}` returns the uploaded documents naming a part and every specification each states, with the page and sentence it came from. Surfaced in the row inspector. Matching is exact, tolerating only case and separators. Nothing is written into the delivered 252 columns; these are proposals for a reviewer.
- **Three sample datasheets** (`data/samples/sample_datasheet_*.pdf`) so the link reproduces from a clean checkout, each naming a part in a catalogue this repository ships.
- **A recorded demo clip** of the live application, regenerated by `scripts/record_demo.py`.

### Fixed

- **Fabricated extraction values.** A real Leviton datasheet produced `material = "s and on installation time."` at confidence 0.85, and a Texas Instruments datasheet produced `material = "Parts may have multiple material finish o"`. A specification now requires a real label and must occupy the remainder of its line. Both defects were found by real manufacturer PDFs and by nothing in the test suite, whose fixtures are all clean label-value sheets.
- **`DuplicatePreparedStatement` 500s.** The managed Postgres sits behind a transaction pooler, which cannot carry session-level prepared statements; psycopg3 auto-prepares after a few executions. This intermittently broke catalogue ingest and put the extraction worker in a failure loop. Both connection pools now disable client-side preparation.
- **Re-uploading a document could never retry it.** Intake deduplicates by content hash and returned `task_id: null` for every repeat, so a failed extraction was permanently stuck. A re-upload now reprocesses when the first attempt produced nothing, and never re-runs over an artifact a human has reviewed.
- Delimiter sniffing for semicolon-separated CSV; identifier columns (`id`, `product_id`) recognised as part numbers; PDFs filed under the workspace they were uploaded to; the dashboard recovering onto the current build after a cached-HTML deploy.

### Changed

- Workspaces are enforced: a batch in one is not listed, readable or deletable from another.
- The README leads with measured results, names every real manufacturer document tested against with its source URL, and separates real data from self-authored fixtures.

### Note on the 1.0.0 figures below

The `94.64%` benchmark and `4,250+ SKUs/sec` recorded for 1.0.0 were not
reproducible when re-measured. The evaluation is now scored on request via
`GET /catalogue/evaluation/synthetic` rather than transcribed, and returns
94.37%. The Pylint score is 9.94/10. The 1.0.0 entry is left as written
because a changelog records what was claimed at the time; this note records
what was true.

## [1.0.0] - 2026-08-14

### Added
- **Multi-Format Ingestion:** Ingest CSV, TSV, XLSX, and PDF files with automatic supplier header mapping and bracket cleaning.
- **Authoritative Sourcing Engine:** Discover verified manufacturer URLs, datasheets, and user manuals while strictly blocking reseller marketplaces.
- **Dynamic 50-Attribute Triplet Engine:** Dynamic mapping for `ATTRIBUTE_LABEL`, `ATTRIBUTE_VALUE`, and `ATTRIBUTE_UOM` (1..50).
- **Domain-Agnostic Intelligence:** Comprehensive coverage across HVAC, Plumbing, Electrical, Machinery, Abrasives, Tools, Lighting, and Consumer Appliances.
- **Dual-Mode System:** Headless batch REST API (4,250+ SKUs/sec) and dark-mode React/Vite Control Center (`localhost:5174`).
- **Human-in-the-Loop (HITL) Review Queue:** Interactive side-by-side evidence inspection, 1-click approvals, and immutable SHA-256 audit logs.
- **Standards & Delivery Syndication:** Official Unilog CX1 252-column template CSV exporter, `schema.org/Product` JSON-LD graph, and flat Commerce PIM format.
- **Evaluation Benchmark Engine:** Ground-truth accuracy scoring (94.64% exact-match rate on 200-row benchmark).
- **Automated CI & Code Quality:** Continuous integration testing with GitHub Actions and 9.86/10 Pylint score.
